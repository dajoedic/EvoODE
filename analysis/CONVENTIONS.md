# analysis/ — Architecture and Conventions

This file is the single source of truth for the structure, rules, and conventions
of the `analysis/` directory.

All Codex tasks for analysis work are written to `codex/CURRENT_TASK_ANALYSIS.md`.
Read this file before implementing any analysis task.

---

## Purpose

`analysis/` contains all Python-based evaluation, aggregation, and plotting logic.

- EvoODE (Julia) produces results
- Python reads and analyzes them
- No cross-import between Julia and Python

---

## Directory Structure

```
analysis/
├── requirements.txt              # Python dependencies, pinned versions
├── CONVENTIONS.md                # This file
├── scripts/
│   ├── aggregate/                # CSV/JSON inputs → processed intermediate data
│   └── plot/                     # Processed data → figures and tables
├── utils/                        # Shared helper functions, no executable __main__ blocks
├── data/                         # Derived, cached intermediate data (never manual inputs)
│   └── <experiment_id>/
├── figures/                      # Generated figures
│   └── <experiment_id>/
├── tables/                       # Generated tables (LaTeX / CSV)
│   └── <experiment_id>/
├── notebooks/                    # Exploratory only, never source of final outputs
│   └── EXPLORATORY_*.ipynb
└── configs/                      # Per-experiment configuration files
    └── <experiment_id>.json
```

### Allowed and forbidden per folder

| Folder | Allowed | Forbidden |
|--------|---------|-----------|
| `scripts/` | `.py` files, deterministic, parameterized via CLI | Notebooks, hardcoded paths, throwaway code |
| `utils/` | Shared helper functions (data loading, plot style, metric computation) | Executable `__main__` blocks, experiment-specific logic |
| `data/` | Derived `.csv` files from aggregation scripts | Manually edited files, raw data copied from `experiments/` |
| `figures/` | `.pdf` and `.png` files, only generated by scripts | Manually created or post-edited files |
| `tables/` | `.tex` and `.csv` tables, only generated by scripts | Manually edited files |
| `notebooks/` | Exploration, prototyping, sanity checks | Final figures, logic that belongs in `utils/` |
| `configs/` | `.json` with paths, parameters, experiment IDs | Data, results, code |

## Execution Philosophy

**Script-based. No exceptions for final outputs.**

- Every final figure and table is produced by a script in `scripts/`.
- Scripts are parameterized via CLI arguments, never hardcoded.
- A figure file is an artifact, not a document. It can be deleted and reproduced exactly by re-running the script. If that is not true, the architecture is broken.

**Source of truth:**

```
Script → produces → Figure / Table
```

---

## Reproducibility Rules

Every figure must be fully reconstructable from:

1. The generating script (in `scripts/`)
2. The raw data (in `experiments/<experiment_id>/runs/` or `outputs/benchmarks/`)
3. The configuration file (in `configs/<experiment_id>.json`)
4. `requirements.txt` (pinned versions)

**Determinism:**

- Analysis scripts are deterministic.
- No randomness except bootstrap confidence intervals — and there the seed is a named constant in the script.
- No `random.seed()` without an explicit comment explaining why.

**Versioning of analysis outputs:**

- `figures/`, `tables/`, and `data/` are in `.gitignore` — they are generated artifacts.
- Exception: when a figure is explicitly frozen for a paper submission, it is copied manually to `paper/figures/` and committed there.
- `data/` is also in `.gitignore`. Intermediate data is not committed; it is regenerated on demand.

## Naming Conventions

### Scripts

Pattern: `<verb>_<subject>.py`

```
scripts/aggregate/aggregate_run_registry.py
scripts/aggregate/aggregate_benchmark.py
scripts/plot/plot_exact_match_rates.py
scripts/plot/plot_stage_overshoot.py
scripts/plot/plot_loss_by_variant.py
scripts/plot/table_main_results.py
```

The filename describes what is produced, not what is read.

### Figures

Pattern: `<experiment_id>/<figure_type>.pdf`

```
figures/paper1_phaseA_v1/exact_match_rates.pdf
figures/paper1_phaseA_v1/stage_overshoot_by_variant.pdf
figures/paper1_phaseA_v1/loss_distribution.pdf
```

Double underscore (`__`) is reserved as separator if experiment ID and figure type
need to be combined in a flat filename (e.g. for paper snapshots).

### Tables

Pattern: `<experiment_id>/<table_name>.tex` or `.csv`

```
tables/paper1_phaseA_v1/main_results.tex
tables/paper1_phaseA_v1/exact_systems_summary.csv
```

### Processed data

Pattern: `<experiment_id>/<data_type>.csv`

```
data/paper1_phaseA_v1/run_registry_processed.csv
data/paper1_phaseA_v1/aggregate_by_variant_system.csv
```

### Configs

Pattern: `<experiment_id>.json`

```
configs/paper1_phaseA_v1.json
```

Contents: path to `run_registry.csv`, system list, variant labels, plot colors, figure sizes.

## Separation of Concerns

```
experiments/<id>/runs/          ← raw data (Julia, never written by Python)
     ↓
scripts/aggregate/              ← reads raw data, writes to data/
     ↓
data/<id>/                      ← cached intermediate data (derivable, not committed)
     ↓
scripts/plot/                   ← reads data/, writes to figures/ and tables/
     ↓
figures/<id>/                   ← generated artifacts (not committed)
tables/<id>/                    ← generated artifacts (not committed)
     ↓
paper/figures/                  ← explicitly frozen, committed submission artifacts
paper/tables/
```

- Raw data is never copied into `analysis/` — always referenced by path.
- Intermediate data in `data/` is cached because aggregation over many runs is expensive.
- Figures are never cached — always regenerated.

---

## Notebook Policy

Notebooks are **allowed, but explicitly secondary**.

Rules:

- Notebooks live exclusively in `analysis/notebooks/`.
- Filenames must begin with `EXPLORATORY_`.
- Notebooks must not write figures to `analysis/figures/`.
- Once a notebook produces a useful result, the logic is transferred to a script. The notebook is not developed further.
- Notebooks are not committed with output cells (clear outputs before committing).
- Notebooks are **never** the source of truth for a paper figure.

## Dependency Management

**`analysis/requirements.txt` with pinned versions. No `>=`.**

Example:
```
pandas==2.2.2
matplotlib==3.9.0
seaborn==0.13.2
scipy==1.13.0
```

- No `pyproject.toml` — `analysis/` is not an installable package.
- No `environment.yml` — Conda is not used.
- Python venv lives in `analysis/.venv/` (in `.gitignore`).
- Julia environment (`Project.toml`, `Manifest.toml`) is fully separate.

Setup (once, manual):
```
cd analysis
python -m venv .venv
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

## Workflow: Adding a New Analysis

Example for a generalization study:

```
1. Raw results exist in studies/generalization_study/results/

2. Write config:
   → analysis/configs/generalization_v1.json
     (path to raw data, system list, variant labels)

3. Write aggregation script:
   → analysis/scripts/aggregate/aggregate_generalization.py
   → produces analysis/data/generalization_v1/aggregated.csv

4. Write plot scripts:
   → analysis/scripts/plot/plot_generalization_loss.py
   → analysis/scripts/plot/table_generalization_summary.py

5. Run scripts:
   → python scripts/aggregate/aggregate_generalization.py --config configs/generalization_v1.json
   → python scripts/plot/plot_generalization_loss.py --config configs/generalization_v1.json

6. Artifacts land in:
   → analysis/figures/generalization_v1/
   → analysis/tables/generalization_v1/

7. For paper submission: copy selected figures to paper/figures/ manually (deliberate step)

8. Commit contains: scripts + config (not figures or data)
```

## Anti-Patterns (forbidden)

| Anti-pattern | Why forbidden |
|---|---|
| Manually edited CSV in `data/` | Breaks reproducibility; not traceable |
| Figure without a generating script | Cannot be reproduced; not an artifact |
| Ad-hoc scripts in `analysis/` root or repo root | No clear owner; never cleaned up |
| Hardcoded paths in scripts | Breaks on other machines; prevents reuse |
| Exploratory notebook as figure source | Notebooks are not deterministically reproducible |
| Committing `figures/` or `data/` | Artifacts and caches do not belong in the repository |
| Script that silently overwrites an existing figure | Can cause silent data loss on misconfigured runs |
| Single script that mixes aggregation and plotting | Violates separation of concerns; hard to debug |
| Analysis scripts that import or call Julia code | The Julia–Python boundary is hard |
| Generating figures directly into `paper/figures/` | `paper/` is an archive, not a build output |
