# REPORT WP-N25c

## Summary

Changed the C-5 planning cost estimate for WP-N3/WP-N4 from
`total_parameter_optimization_time_s / total_loss_evals` to
`elapsed_s / total_loss_evals`.

Julia was not executed in this Codex environment, per `codex/CODEX_PROTOCOL.md`.

## Changed Files

- `studies/regression/wp_n25_phase_c_c5_common.jl`
  - `wp_n25_loss_eval_seconds` now requires `elapsed_s`, checks it is finite and positive, and divides it by `total_loss_evals`.
  - Missing or invalid `elapsed_s` errors include the Phase-C cell key.
  - The estimate row/output column is now `campaign_elapsed_s_per_loss_eval`.
  - `--estimate-cost` output keeps `Planning cost estimate only; not runtime evidence.` and adds the source line `elapsed_s / total_loss_evals`.
- `test/test_wp_n25_phase_c_c5.jl`
  - Added a real-record-derived fixture test where `elapsed_s = 120.0`, `total_parameter_optimization_time_s = 6.0`, and `total_loss_evals = 30`.
  - Expected per-loss cost is `4.0`, proving the helper follows `elapsed_s`.
  - Added rejection tests for missing `elapsed_s`, `elapsed_s = 0.0`, and `elapsed_s = Inf`.
- `SCRIPTS.md`
  - Added a C-5 note that `--estimate-cost` computes from `elapsed_s / total_loss_evals` and is an upper bound assuming every fit exhausts its loss-evaluation budget.

## WP-N5 Cost Path

`studies/regression/wp_n5_ic_generalization.jl --estimate-cost` does not call
`wp_n25_estimate_rows` and does not use `total_parameter_optimization_time_s`.
It has its own estimate in `_wp_n5_write_phase_c_cost_estimate`, based on
`total_simulation_time_s / total_ode_solves`, with `integrations_per_cell = 2`.
No WP-N5 change was made.
